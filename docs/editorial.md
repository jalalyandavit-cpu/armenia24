# Основа редакторской системы

Текущий адаптер данных — `content/articles.json`; шаблоны используют словари статьи, а не вшитые карточки. Можно заменить чтение JSON загрузкой из CMS при сборке, сохранив маршруты `/news/{slug}/` и `/section/{category}/`.

## Текущие поля

`slug` — уникальный адрес латиницей; `category` — politics/economy/society/world/sport/video; `title`, `excerpt`, `body` — армянский текст (body необязателен, абзацы через две новые строки); `image` — путь локального изображения; `imageAlt` — обязательное описание при наличии изображения; `featured` — признак главного материала; `video` — зарезервированное поле, сейчас null.

Сборка добавляет demo=true и status=demo ко всем примерам. Для production следует явно ввести схему с полями id, slug, title, excerpt, body, category, authorId, publishedAt, updatedAt, status (draft/review/published), isDemo, featured, image {url, alt, caption, credit}, video {url, poster, caption, transcript}. Флаг примера должен сохраняться до замены реальными проверенными материалами.

## Этапы подключения

1. Подключить CMS либо API и базу данных. Отделить черновики от публичных данных; публикация только редактором.
2. Аутентификация и роли author/editor/admin. Защита от CSRF, аудит изменений, резервные копии.
3. Загрузка фото и видео в объектное хранилище с проверкой MIME, размеров и расширений; генерация WebP/AVIF и адаптивных вариантов. Видео — с poster, субтитрами и расшифровкой.
4. Валидация полей, уникальности slug и alt. Для форматированного текста использовать безопасный renderer/санитизацию, не вставлять произвольный HTML. Сейчас текст экранируется.
5. Отдельный закрытый предпросмотр черновика, затем пересборка и публикация по подтверждению. Добавить canonical, sitemap, NewsArticle JSON-LD и реальные даты только после настройки домена и настоящего контента.

Секреты CMS должны оставаться на сервере/в окружении сборки. Публичный `data.json` содержит только материалы демонстрации; его нельзя использовать для хранения черновиков или персональных данных.
